# Roadmap

## v0.1 — repository extraction

- Generic problem-pack discovery and validation
- Seven Millennium target maps
- Bounded local Codex round
- Stage-boundary resume
- Sanitized bundle export and static inspection
- Deterministic controller tests

## v0.2 — reliability

- Intentional kill/reboot fixtures
- Attempt-level salvage with new attempt IDs
- Stronger process-tree cleanup
- Stable JSON event schema and migrations
- Content-addressed snapshot store
- Full regression replay of the original private Forge fixture

## v0.3 — public contribution pilot

- Platform-independent static bundle inspection
- Secret scanning and artifact limits
- Research and engine PR templates
- Duplicate claim detection
- Maintainer signing and admission receipts
- One solved benchmark pack with known-good and known-bad submissions

## v0.4 — safe recursive evolution

- Signed successor engine packages
- Sandboxed regression execution
- Finite multi-round activation records
- Automatic rollback on invariant failure
- Longitudinal evidence for prompt/topology changes

## v0.5 — distributed home swarm

- Signed problem/harness registry
- Claim DAG and expiring work leases
- Content-addressed bundle and telemetry storage
- Idempotent asynchronous submission and merge queue
- Cross-user duplicate/conflict detection
- Audit-capacity backpressure and reviewer queues
- Problem-local recursive harness branches
- Heterogeneous model/provider provenance
- Cost, energy, attribution, and abuse controls

## v0.6 — long-horizon research campaigns

- Durable multi-day and multi-month goal queues
- Automatic checkpoint handoff across users and models
- Historical fixture tournaments for harness candidates
- Shadow and canary activation with rollback
- Cross-problem process-learning evaluation
- Public dashboards for dependency-graph delta, verification debt, compute,
  and reviewer attention

## Public beta gate

Public beta requires all of:

1. Three terminal real runs from clean checkouts.
2. One run recovered after an intentional controller kill.
3. One valid and one malicious fixture bundle correctly classified.
4. One problem-pack-independent solved benchmark.
5. External security review of the execution and bundle boundaries.
6. A bounded maintainer review queue and documented response policy.
